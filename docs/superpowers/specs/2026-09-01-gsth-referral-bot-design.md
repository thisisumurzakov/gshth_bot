# Дизайн: Реферальный Telegram-бот Global Shapers Tashkent Hub

Дата: 2026-09-01
Статус: утверждён пользователем

## Цель

Telegram-бот, который регистрирует пользователей, проверяет подписку на канал
Global Shapers Tashkent Hub (GShTH), выдаёт каждому персональную пригласительную
ссылку в канал и открывает доступ в закрытый канал после того, как по этой
ссылке в GShTH вступят 3 человека.

## Стек и архитектура

- Python 3.12+, **aiogram 3** (асинхронный фреймворк для Telegram Bot API).
- **SQLite** через SQLAlchemy 2 (async, драйвер aiosqlite) + **Alembic** для миграций.
- Один долгоживущий процесс, **long polling** (без webhook).
- Хостинг: VPS, запуск через systemd (автоперезапуск при падении).
- Конфигурация через `.env`: `BOT_TOKEN`, `MAIN_CHANNEL_ID`, `PRIVATE_CHANNEL_ID`,
  `ADMIN_IDS` (список Telegram ID через запятую).

Структура проекта:

```
aki-bot/
  bot/
    main.py           # точка входа, регистрация роутеров, allowed_updates
    config.py         # настройки из .env
    db/               # модели, сессии, репозитории
    handlers/         # start, registration, referral, admin
    middlewares/      # подгрузка пользователя из БД, выбор языка
    services/         # ссылки-приглашения, подсчёт рефералов, рассылка
    locales/          # тексты uz / ru / en
  migrations/         # Alembic
  data/bot.db         # файл SQLite
```

## Модель данных

**users**

| поле | тип | описание |
|---|---|---|
| tg_id | integer, PK | Telegram ID пользователя |
| full_name | text | имя и фамилия, введённые при регистрации |
| phone | text | номер телефона |
| language | text | `uz` / `ru` / `en` |
| invite_link | text, nullable | персональная пригласительная ссылка в канал GShTH |
| private_link_sent | boolean | выдана ли ссылка на закрытый канал |
| created_at | datetime | дата регистрации |

**referrals**

| поле | тип | описание |
|---|---|---|
| inviter_tg_id | integer, FK → users | кто пригласил |
| joined_tg_id | integer, **unique** | кто вступил в канал |
| joined_at | datetime | когда вступил |

Уникальный индекс по `joined_tg_id` гарантирует: один и тот же человек
засчитывается только один раз и только одному пригласившему (выход из канала и
повторное вступление не задваивают счётчик).

## Пользовательский сценарий

1. `/start`. Если пользователь уже в базе — главное меню без повторной
   регистрации: статус «приглашено X из 3» либо готовая ссылка на закрытый
   канал, кнопка смены языка.
2. Новый пользователь: выбор языка → ввод имени и фамилии → номер телефона
   (кнопка «Поделиться контактом» или ввод вручную с валидацией формата).
3. Бот предлагает подписаться на канал GShTH (кнопка-ссылка на канал + кнопка
   «Я подписался»).
4. По нажатию «Я подписался» бот проверяет подписку через `getChatMember`:
   - не подписан — вежливое сообщение с просьбой подписаться и повторная проверка;
   - подписан — бот создаёт персональную пригласительную ссылку в канал GShTH
     (`createChatInviteLink`), сохраняет её в `users.invite_link` и отправляет
     пользователю с текстом: «Чтобы получить ссылку на закрытый канал,
     пригласите 3 друзей присоединиться к каналу по вашей уникальной ссылке».
5. Подсчёт рефералов: бот получает обновления `chat_member` канала GShTH.
   Если человек вступил по известной персональной ссылке — записывается реферал,
   пригласившему отправляется уведомление о прогрессе («Присоединилось 2 из 3»).
   Вступление по собственной ссылке (самоприглашение) не засчитывается.
   Вступившим не требуется регистрироваться в боте — считается сам факт
   вступления в канал.
6. На третьем реферале бот создаёт **одноразовую** ссылку в закрытый канал
   (`createChatInviteLink` с `member_limit=1`, чтобы её нельзя было передать),
   отправляет пользователю и ставит `private_link_sent = true`. Процесс завершён.

**Обязательное условие**: бот — администратор обоих каналов (GShTH и закрытого)
с правом «Приглашать пользователей». В `allowed_updates` при запуске polling
обязательно включается `chat_member` (иначе Telegram эти события не присылает).

## Админ-функции

Доступ — по списку Telegram ID из `ADMIN_IDS`. Команды работают только в личке с ботом.

- `/broadcast` — бот просит прислать сообщение. Принимается любой тип: текст,
  фото/видео/документ с подписью, с форматированием. Бот показывает превью и
  кнопки «Отправить» / «Отменить». Рассылка идёт через `copyMessage` всем
  пользователям из базы с ограничением скорости (~20 сообщений/сек — лимит
  Telegram). В конце — отчёт: доставлено N, заблокировали бота M.
- `/message <tg_id или телефон>` — то же самое, но одному пользователю
  (поиск по Telegram ID или номеру телефона из базы).
- `/stats` — количество зарегистрированных, количество получивших доступ в
  закрытый канал.

## Локализация

Три локали: узбекский (`uz`), русский (`ru`), английский (`en`). Все тексты
бота — в файлах локалей (`bot/locales/`), выбранный язык хранится в
`users.language` и подставляется middleware'ом автоматически. Добавление нового
языка — один новый файл локали, без изменения кода обработчиков.

## Обработка ошибок

- «Я подписался» без подписки — повторная проверка по кнопке, без ограничений.
- Пользователь заблокировал бота — при рассылке пропускается и учитывается в
  отчёте; при уведомлении о реферале ошибка логируется и не прерывает подсчёт.
- Перезапуск бота — всё состояние в SQLite, ничего не теряется; long polling
  возобновляется автоматически.
- Повторное вступление реферала — не задваивается (уникальный индекс).
- Ошибки Telegram API (rate limit, flood control) — повторные попытки с
  экспоненциальной задержкой при рассылке.

## Тестирование

- pytest: юнит-тесты логики подсчёта рефералов (дедупликация, самоприглашение,
  порог 3) и репозиториев (на SQLite in-memory).
- Диалоговые сценарии (регистрация, проверка подписки, broadcast) — ручной
  чек-лист на тестовом боте и тестовых каналах.

## Вне рамок (YAGNI)

- Веб-админка (архитектура позволяет добавить позже).
- Экспорт данных, аналитика, планировщик рассылок.
- Изменение имени/телефона после регистрации (добавим при необходимости).
